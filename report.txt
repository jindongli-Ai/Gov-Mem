## Objective and non-negotiable evaluation setup

The submission objective is GateMem paper MGS:

    MGS = U * (1 - A) * (1 - F)

Utility is the priority. Privacy/deletion controls are required, but generic
permissions must not over-refuse ordinary current operational facts. The
pipeline is:

1. Stage 1 retrieval from history/memory bank.
2. Stage 2 LLM semantic rerank and source-local privacy/capability decision.
3. Stage 3 certified slot alignment and minimal realization.

`gpt-5.4-nano-2026-03-17` for all roles. The official GateMem judge is Yunwu
`gpt-4o`, `temperature=0.0`, `max_output_tokens=4096`. Do not compare a
stronger-backbone run against nano baselines or claim local metrics as paper
metrics. Never place API keys in this file or output.

## Confirmed causes of low Utility

1. Stage 3 was over-conservative about redundant ingestion metadata.
   A final current summary can have exact source text and exact slot values but
   no duplicated `provenance.evidence_span` when it came from a heuristic
   extractor. The old final gate discarded it despite Stage 2 having selected
   and authorized the source. This forced a partial answer or a stale fallback.

2. A scalar evidence selection can choose a status predicate instead of the
   fact requested by the user. Example: source t049 contains both the full
   term `fixed twelve-month term plus mutual written renewal` and the status
   field `the current approved structure`. The latter proves recency but is
   not a usable contract-structure answer.

3. The query planner is open-schema and may name the same question fields as
   `approved_budget` or `current_approved_budget`. Stage 3 must use the
   query-grounded support span and source meaning, not require literal schema
   equality.

4. Earlier current state can coexist with later summaries in active storage.
   Stage 2 needs to preserve the canonical current source and Stage 3 must
   realize its exact field. Do not fall back to arbitrary similarly named
   slots such as a replaced budget value.

## Current code changes and rationale

### `src/gov_mem/backbones/rag_policy_amem.py`

- Stage 2 `authorized_for_requester=true` is retained as a source-local,
  attribute-level operational capability for Stage 3.
- It is not a record-wide permission. Stage 3 still enforces exact source,
  slot, lifecycle, deny, and source-span checks.

### `src/gov_mem/governance_runtime/semantic_reranker.py`

- Stage 2 prompt tells the base LLM to retain safe requested operational
  fields even if adjacent fields are protected.
- It also prohibits answering a deleted/earlier predecessor request from a
  current replacement.

### `src/gov_mem/governance_runtime/action_predictor.py`

- Added `label` to deleted-secret detection. This fixed Office ckpt_31, where
  a prompt for a deleted label previously risked using a current replacement.

### `src/gov_mem/governance_runtime/semantic_alignment.py`

- Alignment uses a closed candidate set and LLM-selected SlotNode IDs; every
  selected value must be a verbatim substring of source text.
- A Stage-2-authorized active source may remain eligible when heuristic
  extraction omitted redundant `evidence_span` metadata. Unselected sources
  still require attestation in attestation mode.
- A narrow status-predicate repair was just added: only when the first scalar
  selection has a field name such as `..._is_...`, a single extra base-LLM
  call receives the complete slots of that same source atom and must choose
  the actual requested term/value rather than a deictic status phrase. This
  is the primary v11 change.

### `src/gov_mem/governance_runtime/provenance_authorization.py`

- Mirrors the narrow Stage-2 source exception above. It still requires active
  lifecycle, exact source substring, aligned SlotNode, and no deny/requires-
  permission edge before rendering.

### `src/gov_mem/llm/client.py`

- Logs endpoint/model/attempt/elapsed time/retry class. It does not log
  prompts or keys. These logs established that runtime slowness is Yunwu nano
  traffic, not GPT-4o scoring.
