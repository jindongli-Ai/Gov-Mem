# V8 涨分归因审计与消融方案（尚未执行付费消融）

当前证据说明 V8 有性能提升，但**不能说明涨幅主要由 symbolic reasoning 带来**。
本次只离线读取冻结源码、响应和官方评分，新增分析脚本与测试；没有修改主模型或调用 API。

## 先明确比较对象

- 上一轮浅层 V8：22.1923% → 当前浅层 V8：40.0573%，增加 **17.8650 个百分点**。
- RAG-Naive：19.7491% → 当前 V8：40.0573%，增加 **20.3083 个百分点**。
- 两者不是同一个归因问题。以下先解释最近一次修改的 17.8650 点变化。
- 原文 bank、shallow 模式、RAG Top-20、最多 12 个邻近上下文、公开领域 policy、
  memory/answering 模型和 temperature 在这两轮中没有改变。不能把它们当作本次
  新增涨分的原因；它们相对 RAG-Naive 的价值需要另做架构消融。
- 实际有 7 个 runtime 文件变化，涉及语义提示词、协议与来源、入库时机、时间投影、
  查询 graph 展示以及符号删除否决。两轮同时变化，不能当作单变量实验。

冻结版本：旧 `14ed6a1de3f3d306bd7e7f1b145081b847c91cc205266f74b5af89b56c8a3242`；
新 `1346fd7a2492030d310809430553f9ce6ba9156ee87684d27539a82e71e1941c`。

## 已核实的观察

### 分数主要变化在哪个指标

对 MGS=U(1−A)(1−F) 的三项变化，平均六种替换顺序分摊乘积交互，得到：

| 指标变化 | 分配到的平均 MGS 增量 |
|---|---:|
| Utility 变化 | +4.1121 个百分点 |
| 隐私泄露率变化 | +3.6724 个百分点 |
| 删除泄露率变化 | +10.0805 个百分点 |
| 合计 | +17.8650 个百分点 |

这是**指标层面的算术分解，不是模块贡献**。约 56.4% 的净增量分配给删除指标变化，
不能写成“符号删除模块贡献了 56.4%”。一个模块可能同时影响 U/A/F，多模块也会交互。

### 不只是执行错误减少

按相同 checkpoint 配对：两轮均成功 243 个，旧错新好 43 个，两轮均错 4 个，
旧好新错 **13 个**。47→17 是净变化，不能解读为只修好 30 个且没有回退。

在两轮均成功的相同样本上：

| 问题类型 | 样本数 | 旧版好结果 | 新版好结果 | 改善 / 回退 |
|---|---:|---:|---:|---:|
| Utility：答案与 action 均正确 | 93 | 69 | 76 | 14 / 7 |
| Privacy：不泄露 | 75 | 36 | 40 | 9 / 5 |
| Safety：不泄露删除信息 | 75 | 26 | 47 | 25 / 4 |

共同成功子集仅用于诊断，不替代完整 episode 成绩，也不能消除选择偏差。
但它能排除“所有涨分只是解析成功率变化”的解释。

### 符号层和来源扩展的实际覆盖

- 审计匹配到 **8 个 claim** 被符号层独立从放行改为阻断，其中 6 个涉及删除。
  这是直接执行证据，不是 MGS 贡献；claim 数也不等于 checkpoint 数。
- 其余很多删除阻断由 LLM 先提出，再由程序落实；不能把所有带 symbolic 标签的
  block 都算成符号层独立纠错。
- 新的 graph/ingestion 可见来源选择在 **17 个正常 checkpoint、29 个 claim** 中使用；
  其中 **12 个 checkpoint、24 个 claim** 的对应证据进入 Stage 3。它不是所有问题
  都受益的万能修复，且可能通过实际新增可用证据改善 Utility。
- 来源扩展虽然不读取隐藏 history，但相对原来的 candidate-only 放行限制改变了
  可用证据集合。比较 reasoning 时必须单独控制这个因素。
- 调用次数下降但 tokens 增加，不能宣称 graph 压缩已经提高成本效率。

## 对原因的工作假设（等待消融）

1. **Stage 2 的删除语义与身份边界提示词**：新版明确覆盖 owner、历史恢复、片段、
   确认/比较请求，并要求检查整条 KEEP 中的旧值。许多成功阻断由 LLM 发起，因此它是
   优先验证的解释，不能让提示词增强的贡献被记到符号模块名下。
2. **协议/来源修复及有效事件先入库**：更多有效拒绝不再因冗余字段错误而失败；
   已经有效的事件不会被坏 claim 拖着重复抽取。这同时影响成功率、费用和后续 ledger。
3. **明确绑定的符号删除否决**：直接纠正 LLM 提议的错误放行，有可验证作用；
   但目前不能认定它解释了大部分 17.87 点涨幅。状态投影对 LLM 的间接帮助另算。
4. **可见来源扩展与 graph 视图变化**：可能提供有用证据、减少旧状态干扰，也可能
   造成过度拒绝或信息膨胀。必须分别测，不能以调用数下降代替效果验证。

## 消融分两层，避免“关一个开关”却同时改变多个因素

### A. 论文核心：语言审查、浅层结构和符号执行各有多少独立作用

正式模型始终保留 symbolic/neuro-symbolic reasoning。下面的关闭项只存在于独立
实验 harness，不更改 canonical 配置；它们是用于检验必要性的对照模型。

先做信息匹配的 2×2 主设计：

| 实验 | 提供给 Stage 2 的权限/生命周期表示 | Stage 3 前的领域符号否决 |
|---|---|---|
| Full matched control | 当前结构化浅层视图 | 开 |
| −late veto | 同样的浅层视图与投影 | 关 |
| Flat + veto | 同样事实、ID、作用域、时间、来源，平铺为文本 | 开 |
| Flat neural-only | 同样的平铺信息 | 关 |

严格定义：

- 四组都保留相同可靠解析、来源校验、原文候选、安全证据构造、LLM 权限审查和模型。
  关闭的是**领域规则最终改判**，不是允许伪造来源，也不是关闭所有程序验证。
- 平铺组不能少传有效期、删除事件、身份关系或引文，也不能多传完整 history。
  若要测“无需持久化 ledger”，那是另一组端到端实验，不能冒充仅改变表示的消融。
- Flat + veto 的后端仍保留同一份 typed event 状态供符号层使用，只改变 LLM 看到的
  表示。因此这个 2×2 测的是“结构化展示 × 最终规则执行”的主效应与交互，不是完整
  的“有 graph / 无 graph”系统差异。结论中必须保留这个边界。
- 同一次 Stage 2 输出分支到 veto-on / veto-off，可准确测最终 veto 的直接效应；
  没有发生分支输入变化的 checkpoint 复用完全相同的答案和判断，变化的才生成新答案。
  必须遍历全部 12 个完整 episode、保持全 303 行，不能只报 8 个被拦截样本。
- 分支之前要捕获**通过校验但尚未 critic 的 ledger**。禁止从事后 block 猜原始
  delivery，也不能把 LLM 已决定 block 的 claim 一起放行。当前历史审计存在一个
  原始匹配不明的 veto，不能直接假定其原始状态构造反事实。
- 复用需验证完整 Stage 3 输入/输出与官方判分输入身份。新抽取或状态变化会影响
  后续 checkpoint 时，必须完整重跑，不能沿用旧缓存。该分支实验是条件于共同
  Stage 2 的直接效应，不等于从头移除 symbolic reasoning 的总效应。
- 若为公平对照新增统一信息 scaffold 或改变 prompt，四组里的 Full 也要重测；
  不能拿原来的 40.06% 与使用新 scaffold 的消融组硬比。

在此之后增加 **−persistent ledger**：LLM 只用相同公开 policy、身份信息和
固定来源集合的原文引用审查，不看持久化 typed events/投影，也不做领域符号否决。
它与 Flat neural-only 的对比才用于检验累积 ledger 的帮助。需预先明确来源匹配策略：
若信息供给改变，报告为实际系统级消融；另提供同证据对照，区分记忆覆盖和推理收益。
RAG-Naive 保留为外部基线，不替代上述内部控制。

### B. 最近这次涨分：增量机制定位

在统一稳定协议之上，一次只恢复一个旧语义/旧机制：

| 消融 | 保持什么 | 回退什么 | 优先观察 |
|---|---|---|---|
| −new semantic instructions | 新 JSON contract、源 ID、其余 runtime | 删除恢复/片段确认/身份边界等新增语义；保留旧版一般权限提示 | F、A、拒绝率、U |
| −bound deletion veto | 新提示词、来源、投影、权限 veto | 仅删除事件绑定的领域改判；另区分 deleted 标签执行规则 | F、U、真正改变答案的次数 |
| −source-only selection | 输入提示词里的证据文本与其他处理不变 | 不允许 graph/ingestion-only 引文作为回答 claim | U、协议错误、有效证据覆盖 |
| −advisory projection | 相同存储、抽取与来源策略 | 不折叠旧普通更新；权限/删除信息保留 | tokens、F、旧值混淆 |
| −early valid ingestion commit | 提示词、校验逻辑、原始输入不变 | 有效事件等 claim 成功后才提交 | 错误、repair、tokens、后续状态 |

这些单项删除的差值不能简单相加；至少语义提示 × deletion veto 应检查交互。
新旧协议解析失败本身是工程缺陷：通过固定响应回放报告修复率和回退率，
**不把故意重新引入坏 parser 的崩溃当作论文核心模块贡献**。如果确实重测旧协议，
单独列为可靠性诊断，不与科学消融混为一谈。

## 固定评估与费用顺序

1. 先冻结 hypotheses、开关定义和完整 episode manifest；记录 diff/hash。当前这 12 集
   只用于开发诊断。最终结论要固定不参与修改的 episode 集，并匹配四领域及完整轨迹。
2. 原始对照、每个消融和 baseline 使用相同公开 policy、requester/时间输入、检索、
   embeddings、模型、temperature、预算、repair 上限和 scoring protocol。
   原 baseline 的时间 scaffold 不对称须在公平对照中处理，或单列为限制。
3. 同时报 U/A/F/MGS、action/拒绝率、执行错误、最坏情况 MGS、实际 calls/tokens。
   所有失败保留；不能利用 scorer 对空回答的处理抬高隐私/删除分。
4. 对核心组按 episode 做配对统计与按领域分层的 cluster bootstrap；不能把同集
   checkpoints 当独立样本。每领域目前只有 3 集，置信区间只能探索性解释。
   temperature=0 仍不保证 provider 完全确定，关键比较要做重复运行/随机化运行顺序。
5. 最省钱的第一项是固定 Stage 2 的 veto-on/off 分支，对变化的 Stage 3 输入才付费，
   然后重测完整 episode 的核心语义/ledger 对照。后续结构和费用组按结果优先级执行。
   本文没有启动新的付费消融，不把计划写成已完成的因果证明。
